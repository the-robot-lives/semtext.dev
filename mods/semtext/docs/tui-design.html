*The intended TUI presentation for every component class in the semtext pane: one streamlined view, every element a framed card, children nested inside their parent's frame, the header row is the toggle.* This is the design the v0.6.1 renderer implements; where reality differs, the gap is named and tracked in the defect ledger of render-reference.html. Content never contributes glyphs. Every decoration character comes from the GLYPHS vocabulary; content strings are control-stripped and truncated before drawing. A card's header row is its only control. There is no standalone hide/collapse row anywhere — pressing the header toggles the card, and the glyph direction (▾ open / ▸ shut) plus a counted hint state the truth. One concept per frame. A framed card owns one element; its children draw as smaller frames inside it, never as loose rows beside it. If something deserves its own frame it must be a parsed element.

1 The view model

The pane is *one streamlined view*. The default draws the whole document top-to-bottom exactly like a web page laid out in the terminal: every parsed element renders as a box-drawn framed card, and a child element draws as a smaller frame *inside* its parent's frame — a 2-column inset per depth level, frames within frames, no tree gutters (├── spines live only in the compact outline). Pressing a header toggles that card; shutting a parent collapses its whole subtree with it.

There is no separate focus presentation. Section focus (clicking a card in the outline, or a breadcrumb jump) is the same expanded renderer scoped to that subtree: breadcrumb on top, then the identical frames. The compact outline is not a second mode to maintain — it is what collapse-all produces (▾ collapse all switches to the outline tree; ▸ expand all returns to the expanded view), so the two shapes always agree.

2 Component classes

note, reveal, section, tldr, facts, views, properties, procedure, source, code, npl and the friction markers all draw through one card builder: `┌ ▾ badge ───┐` header open, `┌ ▸ badge · N lines ───┐` shut. The whole header is the button (badge bold for sections; the hint states the size, never a promise of hidden content). Open cards spend the header, the body rows and a bottom border from one shared budget; anything past the budget becomes a counted `… (+N rows)` footer — nothing disappears without arithmetic. A child card renders inside its parent's frame, indented 2 columns per depth (its own header, body, children, bottom border all shift and shrink together). Below 30 columns the frame degrades to a left rule `│ ` plus indent so narrow panes keep text instead of unusable frames. Keys stay document paths, so a nested toggle keeps working after focus scopes the view. Bold with underline rules, never color-only: h1 gets a full-width ══ rule, h2 a full-width ── rule, h3 a ┄ rule exactly under its wrapped text, h4–h6 bold with no rule (h5/h6 dim). Rules span the card's inner width (insets respected) and measure by code points so emoji do not skew them. A blank row sits above a heading unless it opens its frame; a section's title lives in the frame header — never duplicated as a heading row inside. Boxed in the frame, dim, wrapped at word boundaries (indent preserved, over-width tokens hard-cut, code/pre verbatim). `br` variants and literal newlines are hard row breaks; runs of blank lines collapse to one. Text is never dropped just because a tag has no renderer — unknown tags draw their blocks or leaf text in a frame of their own. HTML lists render like the page (v0.6.1): unordered bullets by depth — • top level, ◦ nested, ▪ deeper; ordered items numbered per the ol's start/type attrs as `1.`, `a.`, `i.` with the label right-aligned in a 3-char gutter; task items show ☐/☑ from a checkbox input or a task-list class; dl terms draw bold with their definitions indented under them. Every list row hangs (continuation lines align under the text column, never under the marker), nested lists draw in document order beneath their parent item, and block content inside an item (paragraphs, quotes) keeps its own rows. Same card builder for the whole npl family plus the four Trinity markers (name uppercased, glyph per tag, first attributes in the badge — internal state like collapsed never echoes). Flat siblings by parser contract — one card per phase item, never nested into each other; the same-name implied-end rule also covers the loose leaves sem-note/sem-step/sem-fact. Caption row (▦ rows × cols), then a box-drawn table: ┌─┬─┐ top, bold header, ├─┼─┤, dim body, └─┴─┘. Markdown delimiter rows are separator decoration, never data. Columns shrink from the widest until the frame fits the width; cells truncate with …. Framed body with the ⌨ lang badge top-right. Content dim, tab-expanded, capped at 40 lines with an explicit (+N lines) footer. Raw text only — code never nests elements. Framed list of numbered steps (1 → text), title in the badge, overflow as (+N steps). One line per step, truncated to width. Properties draw 🗂 head then aligned 🔑 key ──▸ value rows — one visual unit, not collapsible (already the terse form). quiz/flashcards draw their run button inside the facts frame; the runner owns the full pane (meter ▰▱, prompt, ▢ a)–d) options, ✓/✗ grading, or 🃏 flip) and returns via ◂ outline / ◂ section. Tab row [● active │ other] as plain buttons, then the active view's body wrapped dim below. Framed body with a badge (glyph + tag name); one frame per element, children consumed into the frame. Misc glyph ·, frame + text, never a dead end. The pane header counts unknowns and names the first four so authors see their typos.

3 States and defaults

- Cards default open. Rationale: the view's promise is "everything visible"; hiding by default was the v0.3 behaviour and read as data loss. - Authored collapsed still respected: a collapsed attribute biases the card's default state, kept on every render until the user overrides. It is never echoed into the badge and never hides text the user asked to see. - The expanded map stores the requested value, so expand-all/collapse-all set a baseline and per-card header toggles keep winning afterwards. Collapse-all *is* the compact outline (the pane switches to the outline tree); expand-all returns to the expanded view. - Oversized bodies are capped at capture with a visible `… (+N chars)` marker on the card, so a swallowed-looking body is always counted, never silent. - Focus starts at the breadcrumb and re-uses the expanded renderer scoped to the subtree; anything past the budget is counted in the shared `… (+N rows)` footer. - A fresh document resets the viewer; re-reading the same source keeps a quiz in progress alive.

4 Glyph vocabulary

One glyph per concept, fixed strings only. Outline glyphs are mostly single-width ASCII/box characters so tree alignment survives; emoji appear only inside card bodies where alignment does not matter.

5 Emphasis, color and dim

- dimColor = secondary: bodies, borders, rules below h2, labels, captions, child counts. If a row is content the user asked to see, it is not dimmed twice. - bold = the one thing to read first: every heading level (h5/h6 also dim), section badges, table header rows. - success/error color only inside quiz grading; warning color only on the unknown-elements header row. No other colors — emphasis is never color-only (bold/rules/dim carry it); the pane stays quiet next to the chat. - Truncation always ends in … and a counted footer (`… (+N rows)` from the frame, `… (+N chars)` at capture). Nothing disappears without arithmetic. The design in one sentence: one streamlined view where every element is a framed card nested inside its parent's frame, the header row is the only control, headings are bold with rules, prose stays boxed with its line breaks, cards default open, friction markers flat, unknown tags honest, and every cut counted. Deviations from this contract belong in the render-reference defect ledger, not in ad-hoc renderer tweaks.
