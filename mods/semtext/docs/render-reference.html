*Every tag the semtext pane knows, how each one parses, glyphs, and renders across the four view modes, plus the defect ledger.* Reference for the Claude Code pane at mods/semtext (v0.5.1). Screens live in tui-screens.html; design rationale in tui-design.html.

1 How the pane reads a document

The parser (hooks/register.tsx parseSemText) walks raw text, lowercases tag names, and builds a tree of SemTextNode (tag, attrs, children, collapsed text, captured content, captured p/heading blocks). Detection fires on any sem-*, npl-*, or Trinity marker tag — markdown-escaped spellings like <WEDGE> included.

Three render roles decide what appears in the expanded view: *heading* (the outline row is the render; children always plan below), *flow* (row plus captured blocks or leaf text; children always plan below), *card* (a dedicated renderer draws the body; children are consumed — except npl cards, whose children re-plan below the card since v0.5).

The parser applies implied end tags inside the NPL family — a friction marker opening closes the still-open marker, and an npl tag closes an earlier open of its own name — plus same-name implied end for the loose leaves sem-note, sem-step and sem-fact (back-to-back unclosed notes/steps/facts render as siblings, never one swallowed body). Same-name nesting for every other sem-* name (nested sem-section) stays legal. This is the fix for Trinity markers being emitted unclosed.

Real answers emit the friction phase as markdown-escaped, unclosed markers: <WEDGE> body … <SHADOW> body … The parser lowercases names, tolerates the backslash-escaped form (the > sits inside the tag src, the escape backslash is stripped from captured bodies), and the implied-end rule keeps the four markers flat siblings so each gets its own outline row and card. npl-mindread and friends normally arrive closed; an unclosed one now also renders as its own card instead of being consumed by its parent.

3 View modes and navigation

- Expanded view (default): source row, stats row (element count, unknown check), toggle row, then the whole outline tree top-to-bottom with each row's content inline under its tree branch (spines kept, branch glyphs blanked as indent). - Compact outline: same source/stats/toggle header, then bare tree rows (glyph + label + child count) — every row click-to-focus. - Section focus: breadcrumb (source › ancestors › leaf), captured blocks (## headings, ▌ quotes, paragraphs), the node's own render, then interactive/npl descendants through the registry, then nav row ◂ outline · ◂ prev · ▸ next. - Quiz/flashcards runner: meter ▰▱ position/total (quiz adds score), prompt, ▢ a)–d) options with ✓/✗ grading and next, or 🃏 flip (hotkey f) for flashcards; end state shows set complete. - Toggle row: compact outline ↔ expanded view, plus collapse-all/expand-all over every card key. - Width: pane body columns, falling back to viewport columns, then a 72-column assumption; all rows truncate to width with … on a code-point basis.

4 Truncation and budget

The pane computes room as viewport rows minus header allowance; the expanded view grants the remainder to the content plan. Renderers spend rows from a shared counter; the first unit that does not fit starts the hidden tail, drawn as one … (+N rows hidden) footer.

| Cap | Value | Effect | | --- | --- | --- | | MAX_TEXT | 4000 chars per node | bodies silently cut (no ellipsis marker) — open defect | | MAX_CODE_LINES | 40 lines | sem-code body cap, frame hides the rest with a count | | MAX_TABLE_ROWS | 10 rows | drawn table hides overflow with (+N rows) | | MAX_BLOCKS | 32 | p/heading captures per node | | MAX_FACT_ITEMS | 50 | quiz/flashcard items per set | | MAX_WIDGETS | 10 | interactive descendants drawn per section focus | | wrap width | pane width − indent | hard cut at width (no word-boundary wrap) — open defect |
