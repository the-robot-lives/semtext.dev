*Every tag the semtext pane knows, how each one parses, glyphs, and renders across the view modes, plus the defect ledger.* Reference for the Claude Code pane at mods/semtext (v0.7.0). Screens live in tui-screens.html; design rationale in tui-design.html.

1 How the pane reads a document

The parser (hooks/register.tsx parseSemText) walks raw text, lowercases tag names, and builds a tree of SemTextNode (tag, attrs, children, collapsed text, captured content, captured p/heading blocks). Detection fires on any sem-*, npl-*, or Trinity marker tag — markdown-escaped spellings like <WEDGE> included.

Two render roles decide what appears in the expanded view (v0.6): *flow* (row plus captured blocks or leaf text, indented; children always plan below) and *card* (a dedicated renderer draws the framed card; children are consumed *into the frame* and draw as nested cards inside it — box-model nesting, a 2-column inset per depth). The old *heading* role is gone: sections are cards whose title lives in the frame header, so nothing renders as a bare heading row any more.

Since v0.6 every framed card shares one builder: the header row is the toggle (`┌ ▾ badge ───┐` open, `┌ ▸ badge · N lines ───┐` shut), there is no standalone hide row, and shutting a card collapses its whole subtree. Prose bodies are boxed and honor `br` variants and literal newlines as row breaks (blank lines collapse); node text caps at MAX_TEXT with a visible `… (+N chars)` marker.

The parser applies implied end tags inside the NPL family — a friction marker opening closes the still-open marker, and an npl tag closes an earlier open of its own name — plus same-name implied end for the loose leaves sem-note, sem-step and sem-fact (back-to-back unclosed notes/steps/facts render as siblings, never one swallowed body). Same-name nesting for every other sem-* name (nested sem-section) stays legal. This is the fix for Trinity markers being emitted unclosed.

3 View modes and navigation

- Expanded view (default): source row, stats row (element count, unknown check), toggle row, then the whole document top-to-bottom as framed cards nested inside their parents (2-column inset per depth, no tree gutters). - Compact outline: produced by collapse-all (the toggle's ▾ collapse all switches to it); bare tree rows (glyph + label + child count) — every row click-to-focus; expand-all returns to the expanded view. - Section focus: the same expanded renderer scoped to the subtree — breadcrumb (source › ancestors › leaf), then the identical frames with document-relative keys (toggles keep working), then nav row ◂ outline · ◂ prev · ▸ next. - Quiz/flashcards runner: meter ▰▱ position/total (quiz adds score), prompt, ▢ a)–d) options with ✓/✗ grading and next, or 🃏 flip (hotkey f) for flashcards; end state shows set complete. - Toggle row: expanded view ↔ compact outline via collapse-all/expand-all over every card key. - Width: pane body columns, falling back to viewport columns, then a 72-column assumption; prose rows wrap at word boundaries and every row still ends in … on a code-point basis when a cut happens; below 30 columns frames degrade to a left rule plus indent.

4 Truncation and budget

The pane computes room as viewport rows minus header allowance; the expanded view grants the remainder to the content plan. Renderers spend rows from a shared counter; the first unit that does not fit starts the hidden tail, drawn as one … (+N rows hidden) footer.

| Cap | Value | Effect | | --- | --- | --- | | MAX_TEXT | 4000 chars per node | cut bodies keep a visible `… (+N chars)` marker on the card (v0.6 — was a silent cut) | | MAX_CODE_LINES | 40 lines | sem-code body cap, frame hides the rest with a count | | MAX_TABLE_ROWS | 10 rows | drawn table hides overflow with (+N rows); columns under the 3-cell floor drop with (+N cols) | | MAX_BLOCKS | 32 | p/heading captures per node | | MAX_FACT_ITEMS | 50 | quiz/flashcard items per set | | wrap width | pane width − indent | prose wraps at word boundaries (indent preserved; break whitespace consumed); tokens wider than the width and code/pre bodies hard-cut, tables truncate cells (v0.5.2) |
