Schema — sem-facts / sem-fact

Contract per conventions.md v0.5. BDD source of truth for test/e2e/sem-facts.cy.js. Changes here precede spec changes precede code. This document renders spec/schema/sem-facts.md; the Markdown file remains the editing source.

The core knowledge primitive: a container of sem-fact items, each a statement plus an optional conclusion, rendered as a plain annotated list, flashcards, or a quiz.

Scope semantics

  • statement (required, first): what is claimed.
  • conclusion (optional): what follows.
  • Container view-as: list (default) | flashcards | quiz.
  • The quiz is a view of the same facts — the fallback derives distractors from sibling conclusions when none are authored. Every sem-distractor is authored content (a wrong answer); the fallback reads those when present, otherwise it samples conclusions from sibling facts in the same container (never conclusion of the fact being asked) — so a quiz works with zero distractor markup, deterministically, with no network and no random source. Distractors mint no records of their own; they decorate their fact's record.

Authoring form

<sem-facts view-as="quiz">
  <sem-fact>
    <statement>The sky is blue.</statement>
    <conclusion>Rayleigh scattering dominates.</conclusion>
    <sem-distractor>Oceans absorb red light.</sem-distractor>
  </sem-fact>
</sem-facts>

Class-form alias (conventions Appendix A): div.sem-facts[data-view-as] › div.sem-fact › .sem-statement, .sem-conclusion; div.sem-distractor.

View contracts

list (default)

Statement (bold marker) + conclusion (indented follow-on). No chrome, no interaction.

flashcards

One card per fact: statement face, conclusion back; flip on click, Space/Enter/F; prev/next buttons + arrow keys. State (current card) is presentation only.

quiz

One question per fact: "Which conclusion follows from: <statement>?" — options = the fact's conclusion + distractors (authored, else derived), shuffled deterministically (seeded from the fact's content hash, stable across runs and across fallback/upgraded); multi-select when ≥ 2 conclusions. Choosing reveals correctness inline; a summary score renders after the last question; data-sem-quiz-complete marks the container. Answers are live presentation state — not extracted, not recorded, never synchronized.

Rendered form

  • Fallback (src/fallback/facts.ts): list view is attribute-level styling only; flashcards/quiz are small DOM builders over the same authored nodes — the statements/conclusions stay in the DOM in authored order.
  • Upgraded (Lit): same DOM contract, richer chrome.
  • JS-off: the list view — every statement, conclusion and distractor readable in order. No view rewrites content.

Events

  • sem-quiz-answer, cancelable — before a choice registers; detail carries the fact id and the chosen option. Canceling is a consumer hook (LMS recording, gated mode); the fallback's own state change never cancels itself.

A11y contract

  • list: a real list; statement/conclusion readable as text.
  • flashcards: buttons with accessible names; flip state via aria-pressed.
  • quiz: fieldset/legend or radiogroup per question; inline feedback text (no color-only); summary is text.

Machine contract

  • Each sem-fact mints one record; fields.statement, fields.conclusion; distractors fold into the fact's record (fields.distractors); view-as never extracted (extraction §5c) — all three views yield identical records, including after answering a quiz to completion.
