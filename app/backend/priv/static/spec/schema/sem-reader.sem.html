Schema — sem-reader

Contract per conventions.md v0.5. BDD source of truth for test/e2e/sem-reader.cy.js. Changes here precede spec changes precede code. This document renders spec/schema/sem-reader.md; the Markdown file remains the editing source.

Reader chrome: outline, reading progress, focus mode, type/color controls, print, audience selector. It mints nothing — it is navigation and preference chrome around the document's content.

Authoring form

<sem-reader controls="outline,progress,focus,type,color,print,audience" outline-depth="3">
  <nav aria-label="Contents">
    <ol>
      <li><a href="#s1">Section 1</a></li>
    </ol>
  </nav>
</sem-reader>

Class-form alias (conventions Appendix A): div.sem-reader[data-controls][data-outline-depth] › the same optional nav.

  • controls: outline | progress | focus | type | color | print | audience.
  • outline-depth: the heading depth the outline tracks; the component may auto-build it, but an authored nav wins and is used verbatim.
  • Placement: document metadata, near sem-agent / sem-audiences; chrome only, not content.

Rendered form

  • Fallback: sticky header (controls) + generated outline from authored headings when no nav is present; the progress bar reads scroll position; focus mode dims everything outside the current section; type/color controls flip a --sem-* token on <html>; the audience control is visible only when a sem-audiences block exists.
  • Upgraded: same behaviors, richer transitions.
  • JS-off: the authored nav renders as a plain list; no chrome.

Events

None. Reader state (current section, font size, color mode, focus on/off) is live presentation state — carried in the hash where shareable, never extracted.

A11y contract

  • The outline is a <nav aria-label="Contents"> with a real list.
  • Controls are buttons/switches with accessible names; focus mode preserves tab order.
  • The progress bar is decorative (aria-hidden) — its state is derivable from scroll.

Machine contract

  • Mints no records — chrome, not content. An authored <nav> inside is plain authored HTML and extracts as generic DOM records.
  • All reader state is invisible to extraction; the invariant holds across every reader interaction.
