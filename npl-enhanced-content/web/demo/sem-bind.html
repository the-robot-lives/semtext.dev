sem-bind — live data on sem-* elements

One hydration pipe for every source: a plain URL (static JSON, no auth), an agent-kit/… shorthand (the agentonomi status routes, bearer-token auth with popup login on 401), or a direct payload property (no server at all — demos and tests). Token lives in localStorage["semtext.bind.token"], per origin, never a cookie.

Static JSON — percent progress

./data/progress-percent.json → {percent, comment}. Progress binds poll (30s default); this one is tightened to 15s via sem-refresh="15" so the refetch is visible in devtools.

{ "percent": 42, "comment": "scouting repos" }

Static JSON — step / steps progress

The fraction form: {step: 3, steps: 7, comment} renders the same meter at step/steps with a step 3 / 7 caption.

{ "step": 3, "steps": 7, "comment": "building KV table" }

agent-kit shorthand + error states

agent-kit/{org}/proj/{project}/progress/{id} resolves to https://agentonomi.com/status/…. Without a session this renders the bind error state — which is the point: a bound element never sits blank and silent. With a token stored (the popup login flow stores it under semtext.bind.token) it hydrates and polls.

Auth flow

On a 401 from any host the runtime opens https://agentonomi.com/embed/authorize?redirect_uri=…&state=… in a popup; the embed posts {type: "semtext-bind-token", access_token, expires_in, state} back and closes. Popup blocked → full-page redirect; the token returns in the #access_token=… fragment and is verified, stored and stripped on the next load.
