Schema — sem-chronology / sem-event

Contract per conventions.md v0.5. BDD source of truth for test/e2e/sem-chronology.cy.js. Changes here precede spec changes precede code. This document renders spec/schema/sem-chronology.md; the Markdown file remains the editing source.

A dated, ordered sequence: a container of sem-event items, each with a when, optional until, optional status, and mixed content (title + prose). The same markup renders as a vertical timeline, a compact list, or a data table — the view is a rendering choice, never a rewriting of the DOM.

Authoring form

<sem-chronology view-as="timeline">
  <sem-event when="2026-01-15" status="done">
    <strong>Kickoff</strong>
    <p>Scope agreed.</p>
  </sem-event>
  <sem-event when="2026-02-01" until="2026-03-01" status="active">
    <strong>Build phase</strong>
  </sem-event>
  <sem-event when="2026-06-01" status="planned">
    <strong>Launch</strong>
  </sem-event>
</sem-chronology>

Class-form alias (conventions Appendix A): div.sem-chronology[data-view-as] › div.sem-event[data-when][data-until][data-status], with <time datetime> inside.

  • view-as: timeline (default) | list | table.
  • when (required, each event): date or ISO 8601 datetime.
  • until (optional): the other end of a range; implied ongoing when the range reaches the present.
  • status (optional, each event): planned | active | done — future/present/past coloring; documents author it explicitly so a static page carries the state.
  • Events stay in authored order; the tier never re-sorts.

Rendered form

  • Fallback: container base style + per-event marker; view-as="table" gets a generated header row from the known attributes (When / Until / Status / content) and grid column alignment — one rule set, all three views.
  • Upgraded: same DOM; the component only re-derives status against "now" for coloring (missing status derived, never overwritten as an attribute).
  • JS-off: identical reading in all three views.

Events

None.

A11y contract

  • Content-only roles: the container is a <dl> or list semantically; each event keeps its heading/prose structure.
  • The table view is a real <table> with headers, so screen readers navigate it natively.
  • status is never color-only — the label text is present.

Machine contract

  • Each sem-event mints one record; fields carry when, until, status; child content is the prose text.
  • view-as never extracted (extraction §5c) — all three views yield the same records.
