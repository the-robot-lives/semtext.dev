Schema — sem-properties / sem-property

Contract per conventions.md v0.5. BDD source of truth for test/e2e/sem-properties.cy.js. Changes here precede spec changes precede code. This document renders spec/schema/sem-properties.md; the Markdown file remains the editing source.

A key/value table. The glossary view turns the same pairs into a term list with anchored terms — one body of content, two presentations.

Authoring form

<sem-properties view-as="glossary">
  <sem-property key="MIME" id="g-mime">Multipurpose Internet Mail Extensions.</sem-property>
  <sem-property key="CORS">Cross-Origin Resource Sharing.</sem-property>
</sem-properties>

Class-form alias (conventions Appendix A): div.sem-properties[data-view-as] › div.sem-property[data-key]; glossary form adds [id] for term anchors, optional <dfn>.

  • key (required, each property): the term / key.
  • value (optional): shorthand when the body is plain text; body content wins when both exist.
  • view-as: table (default) | glossary.
  • id on a property = anchor target for the glossary view's term links; cross-references use plain <a href="#id"> pointing at it (the same pattern as references).

Glossary view (Q2 — resolved)

Resolved this branch: the glossary view is a pure <dl>. No per-term toggle chrome, no disclosure widgets. The view is: <dl> with <dt>key</dd>value pairs, terms wrapped so id-anchored links land correctly, sorted or authored order preserved (authored order). Chrome (a per-term expand) returns only if a consumer demands it; the semantics do not change either way.

Q2 resolved (this branch): pure <dl> for the glossary view; disclosure chrome deferred until a consumer demands it.

Rendered form

  • Fallback: table view = a two-column grid/table from the pairs; glossary view = the <dl> above.
  • Upgraded: same DOM contract; optional sorting in the table view.
  • JS-off: readable in both views.

Events

None.

A11y contract

  • Table view is a real table with headers; glossary view is a native <dl>.
  • Term anchors are focusable targets.

Machine contract

  • Each sem-property mints a record; fields.key (required), fields.value when the shorthand is used, text = body.
  • view-as never extracted (extraction §5c) — table and glossary yield identical records.
