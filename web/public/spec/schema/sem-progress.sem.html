Schema — sem-progress

Contract per conventions.md v0.5. BDD source of truth for test/e2e/sem-progress.cy.js. Changes here precede spec changes precede code. This document renders spec/schema/sem-progress.md; the Markdown file remains the editing source.

A single scalar progress indicator: value, optional label, no children semantics beyond a label. The reader chrome's own progress bar is separate reader state, not this element.

Authoring form

<sem-progress value="0.4" label="Migration"></sem-progress>
<sem-progress value="0.9"></sem-progress>

Class-form alias (conventions Appendix A): div.sem-progress[data-value][data-label].

  • value (required): 0–1.
  • label (optional): accessible name / visible label.
  • No view-as variants; one canonical presentation.
Source typo preserved: the schema file states label ∈ [0,1]; the intent — value is the 0–1 scalar, label is free text — is what this contract means, and the upstream typo is flagged rather than silently corrected.

Rendered form

  • Fallback: a horizontal bar with the value; label above when present.
  • Upgraded: same presentation, animated transitions between values.
  • JS-off: a static bar renders from the attribute alone.

Events

None.

A11y contract

  • role="progressbar" with aria-valuenow/aria-valuemin/aria-valuemax (authored or set on upgrade).
  • aria-label from label when present.

Machine contract

  • One record; fields.value (number), fields.label when present; text empty.
