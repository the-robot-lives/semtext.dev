Schema — sem-embed

Contract per conventions.md v0.5. The element is specced here before any renderer exists — the reference implementation is out of scope until ❓ Q7 resolves. This contract is authored directly as SemText; it has no Markdown twin yet, unlike the other schema documents.

Authoring form

<sem-embed source="../other-semtext.sem.html"></sem-embed>
<sem-embed source="../other-semtext.sem.html#section-id"></sem-embed>
<sem-embed source="../glossary.sem.html" view="g-jwt" mode="card"></sem-embed>

Class-form alias (conventions Appendix A): div.sem-embed[data-source][data-view][data-depth][data-mode], same parameters; the element is authored empty in both forms.

  • source: required. Resolved relative to the containing document. An absolute URL is allowed only when the containing document is itself served from http/https; a document opened from the filesystem (file://) must never fetch over the network (conventions §7 hard rule: no runtime fetch in portable docs), so there source must be a relative path that resolves beside the document. javascript:, data: and every other non-http(s) scheme are never valid — checked on the parsed URL object against the document base, exactly as the sem-md destination allowlist does.
  • view: optional. The id of one block in the referenced document — that element and its subtree are embedded instead of the whole document. A #fragment written in source (../other-semtext.sem.html#section-id) is sugar for the same selection; carrying both is an authoring error (warned; view wins), mirroring the statement-vs-compact-form rule of sem-fact.
  • depth: optional number ≥ 1 — the maximum number of embedding hops this element may still perform, itself included. Absent means the format maximum (❓ Q8 below). A value above the format maximum is an authoring error (warned; clamped to the maximum); a non-number or a value below 1 is an authoring error (warned; treated as absent).
  • mode: optional, inline (default) | card. Presentation only (extraction §5c): card renders the resolved content inside a bordered region labelled with the referenced document and, when one was used, the selected block. The content is identical in both modes; extraction is identical in both modes.
  • The element must be authored empty — content comes only from resolution. Authored children are an authoring error (warned; a renderer must replace them on resolution).
  • id, kind, tags, audience per the global attribute catalog.

Resolution order

  1. Resolve the location. source is resolved against the containing document's location and parsed as a URL. The protocol check runs on the parsed object (never the authored string): a relative path inherits the document's own scheme; an absolute http:/https: URL is admitted only when the host document was served from http/https; every other scheme fails (§ Failure).
  2. Load and parse. The referenced document must be a SemText document — exactly one sem-enhanced-document root, well-formed. Anything else (missing file, unparsable markup, zero or several roots) is a missing-source failure (§ Failure). At build time a failed load must fail the build; in a served-document runtime upgrade (❓ Q7) it must render the visible failure card.
  3. Select. With view (or the #fragment sugar): the element in the referenced document whose id matches, plus its subtree; no match is a missing-source failure. Without a selection: every child of the referenced document's root wrapper except sem-reader (reading chrome is per-document) and agent (metadata about the other document must not leak into this one).
  4. Recurse. sem-embed elements inside the selected content resolve in the same order with depth reduced by one. A cycle or exhausted depth fails that embed, visibly (§ Failure) — never the whole document build.
  5. Sanitise. Embedded content is sanitised exactly as the host document (§ Security): scripts dropped, handler attributes dropped, destinations generated inside embedded content through the same allowlist as the host's own.
  6. Mount. The selected, sanitised content becomes the sem-embed element's children in the distributed document; the element and its source remain as provenance.

Failure, cycles, depth

  • A missing source must fail visibly, never silently drop. The unresolved element renders a visible diagnostic card naming the source and the cause; a build that cannot resolve an embed must fail the build. An empty hole, a console-only warning or a silent skip are all contract violations.
  • Cycles are authoring errors. A document embedding itself, or any document in its own embed ancestor chain, is an authoring error. The offending embed renders the same visible diagnostic naming the cycle, and recursion stops on that path — a cycle never loops the build or the renderer.
  • Maximum depth (decision, ❓ Q8): the format maximum is 4 hops — the host document plus three levels of embedded documents. Deeper is almost always an accident: documents compose far more explosively than inline nesting (which sem-md caps at 16), and a small bound keeps a misdetected near-cycle cheap to stop. The bound is a decision, not a derived constant — revisiting it is an editorial change to this document and the Q8 lean, never a renderer tweak.
  • Depth exhaustion fails the offending embed visibly, exactly as a missing source; sibling embeds are unaffected.

Rendered form

  • mode="inline" (default): the resolved content flows into the host document as if authored there; the element adds no box of its own.
  • mode="card": the resolved content sits in a bordered region headed by the source — the referenced document's title (or its source path) and, with a selection, the selected block's id — linked back to the source document.
  • Upgraded / pre-upgrade / JS-off: the resolved content is authored children of the element in the distributed artifact, so every tier renders it without any embed-aware code; nothing is hidden in any tier (§4.4). Embed-specific behaviour (runtime resolution for served documents, ❓ Q7) is an enhancement layered on an already-readable artifact, never a prerequisite for reading it.

Security

  • An embedded document's scripts are never executed — not in the host page, not in any tier. <script> elements are dropped at resolution (removed, never merely made inert), and on* handler attributes are dropped with them.
  • Embedded content is subject to the same sanitisation as the host: destinations minted inside embedded content pass the same parsed-URL allowlist as the host's own (sem-md machinery); generated chrome classes and runtime tier markers inside embedded content are chrome and session state exactly as they are in the host.
  • The network rule stands per containing document: a file://-opened document must never fetch — its embeds are local, relative, and resolved at build time (❓ Q7). Only a document served from http/https may name an absolute http(s) source.

Events

None.

A11y contract

  • Resolved content participates in the host document as ordinary content — real headings, real buttons, light DOM, nothing in a shadow root (§4.5); embedded headings enter the sem-reader outline exactly as authored ones.
  • Card mode's region is labelled with the source; the failure diagnostic is real text, never colour alone.

Machine contract

  • The embed is transparent — it mints no record (the sem-source precedent): extraction descends into the resolved content as if it were authored in place.
  • Extraction invariant (normative, per conventions §8). For a document D in which every sem-embed has resolved, and D′ the same document with every <sem-embed> physically replaced by its selected content: E(D) = E(D′) — deep equality of the record array, including sourceOrder. An embed must produce the same extraction as the inlined content; no consumer can tell a resolved embed from hand-inlined markup by extraction alone. The §8 chain E(D) = E(R(D)) = E(I(R(D))) then applies to the resolved document unchanged.
  • Consequence (❓ Q7): extraction is a total, pure function — no I/O (extraction §9) — so it can never resolve an embed itself. Resolution must happen before distribution; the invariant is stated over the distributed (resolved) artifact, and an unresolved sem-embed reaching a distributed document is a build error, not an extraction mode.
  • mode never changes extraction (both modes carry the same content); depth is a build-time bound and is not reported; source is provenance on the wrapper and is not extracted — the records of embedded content carry no marker of their origin, so an author who wants provenance in the records must inline the content beside a sem-note instead.
Open (Q7, §10) — decision wanted: resolution timing — build-time inlining by the CLI vs runtime fetch in the browser. Recommendation: build-time inlining. Runtime fetch in the browser collides with two normative rules: the §7 hard rule (no runtime fetch in portable docs — a double-clicked file must work with zero network) and extraction purity (extraction §9: no I/O), without which E(D) = E(R(D)) cannot hold across an unresolved/resolved boundary. Build-time resolution keeps the distributed artifact self-contained and machine-identical to hand-inlined markup; a served-document runtime fetch can exist only as a non-canonical enhancement on top of an already-resolved artifact. Open (Q8, §10) — decision wanted: the maximum embed depth. Recommendation: 4 — the host plus three hops: enough for spec → runbook → checklist compositions, small enough that a near-cycle the detector missed stops cheaply. Recorded here as a decision to revisit, not a derived constant. Root spec — §7 distribution hard rules, §8 the extraction invariant. Extraction contract — §5c presentation parameters, §9 purity.
