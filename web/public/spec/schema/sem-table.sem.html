Schema — sem-table

Contract per conventions.md v0.5. BDD source of truth for test/e2e/sem-table.cy.js (including the extraction invariant's recorded reordering exception). Changes here precede spec changes precede code. This document renders spec/schema/sem-table.md; the Markdown file remains the editing source.

A real HTML <table> (the author writes it — headings, groups, captions, whatever the table needs) with optional sort/filter controls. No data model is introduced: the DOM is the data.

Authoring form

<sem-table controls="sort,filter" sticky>
  <table>
    <thead>
      <tr><th scope="col">Name</th><th scope="col">Value</th></tr>
    </thead>
    <tbody>
      <tr><td>alpha</td><td data-value="1">one</td></tr>
    </tbody>
  </table>
</sem-table>

Class-form alias (conventions Appendix A): div.sem-table[data-controls][data-sticky] › authored <table> with <th scope="col"> and td[data-value] sort keys.

  • controls: sort | filter — per-column sort buttons and/or a filter input rendered into the header.
  • sticky: flag — the header row sticks on scroll.
  • data-value on a cell: explicit sort/filter key overriding the cell text.
  • data-filter on a cell: extra haystack text for the filter beyond the cell's text.
  • The author owns the markup: scope, colspan, caption, colgroup all pass through untouched.

Rendered form

  • Fallback: sort = DOM row reordering + arrow state on the active column; filter = row hidden for non-matching rows, match count announced; sticky via CSS.
  • Upgraded: same operations, animated reordering.
  • JS-off: the authored table, sortable/filterable not at all — and that is a valid reading.
  • Print: rows print in current (possibly sorted) order; the filter is a state, not a mutation — clearing restores all rows.

Events

  • sem-sort, cancelable — before a column sorts.
  • sem-filter, cancelable — before the filter applies.

A11y contract

  • Sort buttons carry aria-sort on the sorted column; filter input has an accessible name and the result count is announced politely.
  • The table keeps its native semantics — no ARIA grid overlay is required because the operations are plain DOM changes.

Machine contract

  • One record for the block; text = the table serialized as plain text (rows in document order); fields.controls, fields.sticky.
  • The recorded exception: sorting reorders rows in the DOM, so a naive extractor inside an interaction would see a different order. The handler stamps each row with data-sem-source-index at bind time, and the extraction contract's exception clause (extraction §5) makes sorting the one interaction whose effect is visible in E(I(R(D))) — as a stable, invertible permutation of an unchanged record set, never a content change. Filtering, which hides rather than moves, is not covered by the exception: extraction ignores hidden rows the same way it ignores any hidden element — they are still in the array.
