Schema — sem-procedure / sem-step

Contract per conventions.md v0.5. BDD source of truth for test/e2e/sem-procedure.cy.js. Changes here precede spec changes precede code. This document renders spec/schema/sem-procedure.md; the Markdown file remains the editing source.

An ordered sequence of steps with a completion state per step. Progress is presentation; the authored status is content.

Authoring form

<sem-procedure>
  <sem-step status="done">Install the CLI.</sem-step>
  <sem-step status="active">Run the migration.</sem-step>
  <sem-step>Verify the schema.</sem-step>
</sem-procedure>

Class-form alias (conventions Appendix A): div.sem-procedure › div.sem-step[data-status].

  • status (optional, each step): done | active | blocked — authored explicitly; the tier never derives it.
  • Steps are numbered by position; content is mixed (prose, nested lists, code).
  • Nested sem-procedure inside a step is legal and indents.

Rendered form

  • Fallback: ordered list chrome — position number, status marker per step; no interactivity.
  • Upgraded: same chrome; an optional step-through mode (check off steps) whose state is presentation only.
  • JS-off: identical reading.
  • Print: statuses and numbers visible; no chrome.

Events

  • sem-step-activate, cancelable — before a step becomes active in the step-through mode.

A11y contract

  • An ordered list semantically; step status never color-only — the status word is in the DOM.
  • The step-through mode uses buttons with accessible names; state changes announced politely.

Machine contract

  • Each sem-step mints a record; fields.status (verbatim, null when absent), text = step prose; position is sourceOrder.
  • Step-through state is never extracted — the invariant holds across it.
