Schema — sem-code

Contract per conventions.md v0.5. BDD source of truth for test/e2e/sem-code.cy.js. Changes here precede spec changes precede code. This document renders spec/schema/sem-code.md; the Markdown file remains the editing source.

A code block with a language, an optional filename, optional marked lines, and a control set. The content is always a real <pre><code> pair — a code block whose content is not in the DOM is not a code block.

Authoring form

<sem-code lang="js" filename="app.js" mark="3,5-7" controls="copy,wrap">
  <pre><code>const x = 1;
const y = 2;
return x + y;</code></pre>
</sem-code>

Class-form alias (conventions Appendix A): div.sem-code[data-lang][data-filename][data-mark][data-controls] › <pre><code>.

  • lang (optional): language hint; the tier sets class="language-<info>" on the inner code for highlighters.
  • filename (optional): label shown in the header.
  • mark (optional): comma list of line numbers / ranges (3,5-7) — highlight; del:2,add:4 — diff tint (delete red / add green).
  • wrap (optional): boolean; default wrap off (overflow scrolls); the toggle inverts it.
  • controls (optional): copy | wrap — toggles rendered into the header.
  • Exactly one <pre> child containing exactly one <code> child; nothing else inside the pre.

Rendered form

  • Fallback: header (filename left, controls right) + pre; data-mark applied by src/fallback/highlight.ts — line boxes for marks, diff tint for del:/add:, no token-level highlighting (no dependency).
  • Upgraded: same DOM; syntax highlighting optional (reads language- class if a highlighter is present); copy button uses the Clipboard API with a document.execCommand fallback.
  • JS-off: readable, marked, scrollable; copy unavailable.

Events

  • sem-copy, detail: {text} — after a successful copy; not cancelable.

A11y contract

  • Header is plain text; controls are real buttons with accessible names.
  • Marked lines carry no color-only meaning — a data-mark attribute stays on the element for AT and tools.
  • Content keeps its native <pre><code> semantics.

Machine contract

  • One record; fields carry lang, filename, mark; text is the verbatim code content from the pre.
  • Line numbers are positional in the extracted text, so mark stays meaningful downstream.
