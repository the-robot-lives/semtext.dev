Schema — sem-references / sem-reference

Contract per conventions.md v0.5. BDD source of truth for test/e2e/sem-references.cy.js. Changes here precede spec changes precede code. This document renders spec/schema/sem-references.md; the Markdown file remains the editing source.

A bibliography: sem-reference entries (any content model, defaulting to prose) plus the inline citation element sem-ref that points at them. Citations are plain <a href="#id"> links — no widget.

Authoring form

<p>As shown<sem-ref target="smith2024"></sem-ref>, the mechanism holds.</p>

<sem-references kind="bibliography">
  <sem-reference id="smith2024" role="listitem" href="https://example.com/smith" cite="Smith 2024">The mechanism.</sem-reference>
</sem-references>

Class-form alias (conventions Appendix A): div.sem-references[data-kind] › div.sem-reference[id][data-href][data-cite]; citations are plain <a href="#id">.

  • id (required, each reference): the anchor target of the citation link; document-unique.
  • href (optional): external target; renders as a link on the cite label.
  • cite (optional): the rendered label; the id renders when absent.
  • kind (container): bibliography | footnotes — presentation grouping only.
  • role="listitem": authored on entries (and role="list" on the container) so the machine reading sees the list structure without JS.
  • sem-ref: inline citation; target = reference id; renders as the citation link (numbered or labeled per the container's kind); empty content is legal — the label comes from the reference.

Rendered form

  • Fallback: the container renders entries as an ordered list; each sem-ref becomes an anchor link to its entry; a missing target is a console warning + an inert marker, never a broken page.
  • Upgraded: same DOM; hover previews of the target entry where practical.
  • JS-off: citations are still plain anchors; the list reads as authored.

Events

None.

A11y contract

  • Entries form a real list with roles present in the authored DOM.
  • Citation links have accessible names (the cite label or entry id).

Machine contract

  • Each sem-reference mints a record; fields.href, fields.cite, prose text; id joins it to citations.
  • sem-ref mints no record of its own — it is a citation edge; consumers reconstruct the edge from target + the reference's id if needed.
