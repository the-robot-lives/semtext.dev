auth-notes · refresh tokens

Working notes on the refresh-token grant — sections shallow enough to navigate, records plain enough to render.

Token lifetime

Two grants, two clocks. The access token is short-lived and widely distributed; the refresh token is long-lived and narrowly held.

Access vs refresh

An access token authorizes one call at a time and expires fast, so a leak has a short runway. The refresh token only ever talks to the token endpoint, which keeps its blast radius small.

Rotation on use

Each refresh exchange retires the presented token and mints a new pair. Replaying a retired grant is a theft signal, not a stale retry.

Storage

Where a client keeps the refresh grant decides what a compromise costs.

Browser storage

localStorage is readable by every script on the origin. An HttpOnly cookie or an in-memory holder keeps the grant away from page scripts entirely.

The refresh exchange

    │  refresh grant             │
